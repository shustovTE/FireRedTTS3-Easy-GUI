# VoxCPM2 Full от исходной Base на Dialogs и подтверждённом Scripted

Рецепт рассчитан на одну GPU. Источники заново читаются из закреплённой версии Dialogs и архива Common Voice Scripted 27.0 Russian. Spontaneous и прежние обученные веса в этот эксперимент не входят.

| Источник | Какие записи участвуют в отборе |
|---|---|
| Dialogs | Полный `metadata.csv` ревизии `a74ff44d8d27ca3d21098ea3ed4d31a32923fbdd`, существующий WAV и `emotion=neutral`. Проверяются моно, фактическая длительность и клиппинг. |
| Scripted | Членство в `validated.tsv` и совпадение с текстом в `validated_sentences.tsv` по `sentence_id`. Предложения из `reported.tsv` исключаются. |
| Оба корпуса | Целые реплики с конечными `.`, `!` или `?`, в том числе перед закрывающими кавычками. Проверяются начало, скобки, кавычки, многоточия и неоднозначные сокращения. Проверка формальная. Квот по дикторам или категориям нет. |

Silero VAD 6.2.3 оставляет до 200 мс исходного звука до первой и после последней обнаруженной речи. Внутренние паузы сохраняются. Длительность проверяется по числу отсчётов полученного WAV. В train допустимы **от 3 до 30 секунд включительно**, как для target, так и для reference. В validation действует верхняя граница 30 секунд. Длинная запись может пройти, если после удаления внешней тишины укладывается в лимит целиком.

## Разделение и повторы

Для Dialogs резервируются целые сессии с ориентиром 10% длительности каждой пары актёров. У Scripted одинаковые последовательности слов попадают в один split с учётом текстов Dialogs. Это собственное разделение полного исходного корпуса. Для оценки на прежних примерах или официальных test-строках сперва проверьте пересечения с новым train. Референс берётся у того же диктора в том же корпусе и split, с другим текстом и отличающимся аудио. Записи без такого референса исключаются.

Баланс общий для двух корпусов, только в обучении. Секунда определяется округлением к ближайшей целой, половина округляется вверх. Например, 3,499 с относятся к корзине 3, а 3,500 с к корзине 4. Метки 3 и 30 ограничены точными пределами диапазона.

1. Все уникальные обучающие пары входят как минимум один раз. Базовое число предъявлений каждой корзины равно числу записей самой многочисленной корзины.
2. Порция пустой корзины делится между ближайшими непустыми слева и справа. На краю весь объём получает единственный сосед. При нечётной порции разница между долями составляет одно предъявление.
3. Минимум 30% всех предъявлений имеют `?` где-либо в транскрипте. Для достижения доли меняется распределение дополнительных повторов внутри корзин. Если сохранить все записи, объём корзин и долю вопросов одновременно невозможно, подготовка сообщает максимально достижимое число вопросов.
4. Создаётся отдельный `balanced-train.jsonl` с повторными ссылками на те же WAV. Обычный `train.jsonl` содержит уникальные пары. Validation сохраняет естественные частоты. Процент вопросов измеряется по предъявлениям в эпохе, не по уникальным предложениям или каждому отдельному батчу.

## Подготовка на Gauss

```bash
cd /opt/firered-tuning
git pull --ff-only origin feat/russian-tts-adaptation
mkdir -p training/logs
nohup bash scripts/prepare_voxcpm2_full_ru_30s.sh \
  > training/logs/voxcpm2-dialogs-scripted-30s-prepare.log 2>&1 < /dev/null &
tail -n 20 -f training/logs/voxcpm2-dialogs-scripted-30s-prepare.log
```

Используется прежняя `.venv-voxcpm2`, `models/VoxCPM2` и архив в `training/raw/common-voice-scripted-27-ru`. Если архив отсутствует, сначала выполните `.venv-voxcpm2/bin/python -m fireredtts3_local.common_voice_scripted download`. Загрузчик Dialogs повторно использует проверенные WAV из `training/raw/dialogs` и докачивает недостающие. Подготовка работает после отключения SSH. В логе дождитесь `[prepare] COMPLETE`. `Ctrl+C` завершает просмотр лога.

```bash
jq '.balance | {unique_targets, target_draws, question_draws, question_fraction, base_draws_per_second, empty_bin_transfers, buckets}' \
  training/datasets/voxcpm2-dialogs-scripted-30s/report.json
jq '{updates, target_draws, extra_draws_after_epoch}' \
  training/recipes/voxcpm2-dialogs-scripted-30s-full.audit.json
```

В каждой корзине поле `max_draws_per_clip` показывает максимальное число предъявлений одной записи за эпоху. Равный вес редкого длинного интервала может привести к тысячам повторов одного голоса и текста. Оценивать вклад такого интервала следует по числу уникальных записей вместе с числом предъявлений.

## Запуск Full

```bash
cd /opt/firered-tuning
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 \
  .venv-voxcpm2/bin/python -m fireredtts3_local.voxcpm_training start \
  training/recipes/voxcpm2-dialogs-scripted-30s-full.yaml \
  --job-dir training/jobs/voxcpm2-dialogs-scripted-30s-full

tail -n 30 -f training/jobs/voxcpm2-dialogs-scripted-30s-full/job.log
```

Начальные веса — `openbmb/VoxCPM2` ревизии `7936080b41163874f38610f46f438e2c0757f9fd`. Используется официальный Full-тренер с замороженным AudioVAE и пиковым LR `1e-5`. Планировщик рассчитан на одну полную сбалансированную эпоху. Эффективный батч — наибольший делитель числа предъявлений до 16 включительно, чтобы обучить последнюю запись и закончить ровно на границе эпохи. При 28 базовых порциях это 16 или 14. Микробатч — 2. Валидация вызывается каждые 500 обновлений и на финальном шаге, официальный тренер считает loss максимум на 10 батчах. Сохранения включают середину прогона и финал.

Файлы весов будут в `training/outputs/voxcpm2-dialogs-scripted-30s-full/`. Полный фоновый запуск проверяет свободное место для чекпойнтов до загрузки модели. Подготовка и обучение запускаются отдельно.
