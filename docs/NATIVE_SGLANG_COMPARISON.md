# Нативный генератор и развёрнутый SGLang: одни веса и референс

Этот тест сравнивает два целых текста («Смотрите, по городам…» — 745 символов,
«Тимофей, да…» — 460 символов) тремя способами:

1. Родной `FireRedTTS3Base.generate` из bundled upstream, SDPA, без компиляции.
2. Уже работающий SGLang, обычный WAV.
3. Тот же SGLang, поток PCM, сохранённый в WAV без проигрывателя бота.

## Запуск на Gauss

Сервер должен уже принимать длинный текст и использовать опубликованный этап 07.
Перезапуск или перенастройка сервера для этого теста не выполняются.

```bash
cd /home/firered-tuning
git pull --ff-only origin feat/russian-tts-adaptation
bash scripts/compare_native_sglang.sh
```

Контейнер по умолчанию — `sglang-fire-tts-firered-tts3-1`, голос —
`Dovbish_Anastasiia`. Другие значения можно передать первым и вторым аргументом.
Скрипт печатает новую папку `training/eval/native-sglang-07-XXXXXXXX`.
Сначала создаются два нативных результата, затем четыре SGLang-результата.
Нативный процесс освобождает GPU перед HTTP-запросами; сервер остаётся запущенным.

Повтор с другим seed сохраняется в отдельную папку:

```bash
DIAG_SEED=1235 bash scripts/compare_native_sglang.sh
```

## Что зафиксировано

- Один WAV и точный текст референса извлекаются из сохранённого голоса.
  Оба генератора получают эти bytes и transcript, а SGLang-запросы передают
  референс явно. Хеш сверяется перед использованием.
- Локальный export `training/exports/FireRedTTS3-Base-Russian-20s-07` сверяется
  с manifest и provenance пакета в контейнере. Несовпадение прерывает тест.
- Нативный генератор загружает **те же слитые safetensors**, а не заново сливает
  LoRA. Временная структура каталогов содержит ссылки на шарды и исходный
  native core config. Исходная base, её токенизатор, RedAE и CAM++ проверяются
  по fingerprint экспортированного релиза. Большие файлы не копируются.
- Russian, seed=1234, stop_threshold=0.5, n_timesteps=10, inference_cfg=2.0,
  минимум 6 и максимум 400 аудиопатчей. Оба текста идут целиком, без разбиения
  и внешней нормализации текста. Параметры сервера могут ограничивать запрос
  дополнительно; проверяйте завершение и полноту произнесённого текста.
- Нативный код и SGLang используют разные реализации вычислений и могут
  использовать разные последовательности случайных чисел при одном seed.
  Побайтового совпадения звука ожидать не следует. Этот тест выделяет влияние
  всего runtime; сам по себе он не доказывает ошибку конкретно энкодера.

## Результаты

| Текст | Native | SGLang WAV | SGLang stream |
|---|---|---|---|
| Города | `native/cities.wav` | `sglang/cities/long_full.wav` | `sglang/cities/long_stream.wav` |
| Тимофей | `native/timofey.wav` | `sglang/timofey/long_full.wav` | `sglang/timofey/long_stream.wav` |

`comparison.json` содержит длительности, причины завершения и идентификаторы
релиза/референса. `*.levels.json` — RMS и peak по односекундным окнам.
Это уровни сигнала, не LUFS и не оценка качества: паузы и разные фонемы влияют
на RMS. Никакая нормализация громкости к результатам не применяется.

Для native дополнительно сохраняются `*.float.wav` и `*.raw_levels.json`:
так значения выше диапазона PCM16 не теряются из-за насыщения при записи
обычного WAV. Нативные `*.stop_scores.json` фиксируют stop в свободной генерации.
Исходные запросы, заголовки и HTTP-ошибки остаются в SGLang-подпапках.

Готовый `comparison-audio.zip` содержит сгенерированные WAV, уровни и сводку.
Референсный WAV, его расшифровка и HTTP-запросы с base64-референсом в архив
не включаются. При ошибке одного backend промежуточные файлы сохраняются,
но итоговая успешная сводка/архив не создаются.

Если native чистый, а оба SGLang-варианта портятся, следующий шаг — сравнить
кодирование референса, сгенерированные латенты и декодирование по отдельности.
Если плох только streaming, первым проверяется потоковый путь. Если дефект
слышен и в native, круг причин включает модель, её авторегрессию и референс;
это всё ещё не доказательство проблемы именно обучающего датасета.

## Контроль исходной base без LoRA

Если дефект есть и в native, сравните его с исходной предобученной моделью:

```bash
cd /home/firered-tuning
git pull --ff-only origin feat/russian-tts-adaptation
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 \
  .venv/bin/python -u -m fireredtts3_local.native_comparison baseline
```

Команда выбирает последнее завершённое сравнение в `training/eval/native-sglang-07-*`
и печатает его путь. Для выбора конкретного прогона передайте путь после `baseline`.
WAV/текст референса, оба целевых текста, seed и stop берутся из этого прогона.
Проверяются fingerprint исходной base и остальные параметры генерации.
Загружается непосредственно `models/FireRedTTS3`, без слитых весов или адаптера.
Контейнер и его модель не меняются, запросы в SGLang повторно не отправляются.

Две новые записи и их float-версии сохраняются в `native-base/` рядом с прежним
`native/`. Команда отказывается перезаписывать существующий `native-base/`.
Архив `native-base-audio.zip` содержит исходную base и прежние нативные результаты
дообученной модели вместе с настройками и уровнями, без записи/текста референса.
Проверки упаковки выполняются локально; реальный синтез требует GPU на хосте.
