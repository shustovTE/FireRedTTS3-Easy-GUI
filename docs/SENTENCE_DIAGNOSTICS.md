# Длинный текст целиком и по предложениям

В предыдущей диагностике меньшая длительность и слабый рост RMS иногда
сопровождались пропуском целых фрагментов текста. Этот тест проверяет полноту
речи отдельно от её уровня: **base, backbone-only и DiT-only**, два прежних
длинных текста, каждый целиком и по законченным предложениям.

Используются исходная base и компоненты **checkpoint 143** из `joint-10`.
`backbone_only` включает только обученную LoRA backbone; `dit_only` — только
обученный DiT. `dit_head`, `stop_head`, RedAE и извлечение голоса во всех
вариантах исходные. Это диагностическое смешивание совместно обученных
компонентов, а не три отдельно обученные модели.

## Запуск на Gauss

```bash
cd /home/firered-tuning
git pull --ff-only origin feat/russian-tts-adaptation

OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 \
  .venv/bin/python -m fireredtts3_local.sentence_diagnostics start
```

Нужны исходная base, `checkpoint-step-000143`, recipe и исходный benchmark
`joint-10` с reference WAV и отчётом генерации шага 0. Новый предрасчёт признаков
и датасеты не нужны. Запуск фоновый, SSH можно отключить.

По умолчанию берутся `cities_seed1235` и `timofey_seed1235`. Из них получаются
10 и 5 предложений: **51 нативная генерация**, затем **12 итоговых WAV** и
12 ASR-проверок. На GPU загружается один вариант модели за раз. После завершения
генерации процесс с TTS завершается, и отдельный процесс выполняет ASR на CPU.

ASR использует `faster-whisper large-v3`, CPU int8, четыре потока. При первом
использовании могут скачаться веса распознавателя; готовый кэш используется
повторно. CPU-распознавание может занять больше времени, чем генерация. Во время
этой фазы отсутствие нагрузки на GPU нормально. Версии библиотек, настройки и
хэши файлов ASR сохраняются; при продолжении их изменение отклоняется.

## Условия сравнения

- CFG **2**, STOP **0.5**, 10 шагов flow, seed **1235**, исходный reference.
- `whole`: весь текст одним вызовом, встроенное разделение текста выключено.
- `sentences`: отдельный вызов на каждое законченное предложение. Контекст
  генерации и seed сбрасываются; каждый раз используется **тот же исходный
  reference**, а не звук предыдущего предложения.
- Исходные float-волны соединяются с **200 мс тишины** между предложениями.
  Нет изменения громкости отдельных частей или сглаживания стыков. Для
  прослушивания применяется один постоянный коэффициент ко всему готовому WAV,
  только если нужен запас до пика 0.98. Исходные float WAV остаются локально.
- Разделитель сохраняет весь нормализованный текст. Он учитывает базовые
  сокращения, инициалы и десятичные точки; это простой разделитель для
  контрольных реплик, не универсальный лингвистический анализатор.
- Все итоговые WAV распознаются одним ASR с одинаковыми настройками, без
  подсказки исходного текста, без VAD и без переноса ASR-контекста между окнами.

У исходных длинных генераций остаётся нативный лимит 400 патчей / 64 секунды.
У предложения этот лимит применяется отдельно. Длительность склеенного WAV
включает добавленные паузы. Сравнение меняет длину контекста и способ генерации;
оно не изолирует только один внутренний механизм модели.

## Логи и результат

```bash
.venv/bin/python -m fireredtts3_local.sentence_diagnostics status

tail -n 30 -f training/jobs/joint-10-sentences/job.log
```

`Ctrl+C` закрывает просмотр лога. В `status` видны этап `diagnostics` или `asr`,
количество сгенерированных частей `generated` и проверенных WAV `scored`.
После `[job] Completed successfully.`:

```bash
.venv/bin/python -m fireredtts3_local.sentence_diagnostics summary

ls -lh training/eval/joint-10-sentence-diagnostics/diagnostics-*.zip
```

Пришлите `diagnostics-report.zip` и все `diagnostics-audio-*.zip` из этого
каталога. Аудиоархивы содержат только 12 итоговых WAV:

```text
comparison-audio/{base,backbone_only,dit_only}/{whole,sentences}/case-00.wav
comparison-audio/{base,backbone_only,dit_only}/{whole,sentences}/case-01.wav
```

`case-00` — «Города», `case-01` — «Тимофей».

Основной результат — **`comparison.json`**, `comparison.csv` и `comparison.md`.
Для каждого WAV доступны:

- полный распознанный текст и временные метки слов;
- WER, количества удалений / замен / вставок относительно заданного текста;
- `asr.missing_spans`: непрерывные фрагменты текста, помеченные выравниванием
  как пропущенные; индексы слов начинаются с нуля, конец интервала не включён;
- изменение WER относительно base при том же способе генерации, и относительно
  цельного текста при тех же весах;
- уровень по секундным окнам, изменение RMS между первыми и последними
  10 секундами, границы предложений и причина остановки каждой части.

Сначала проверяем `reproduction_controls_complete` и
`reproduction_review_required`: цельная base должна воспроизвести прежний
контроль. Затем сравниваем полноту текста, тембр, голос и стыки предложений.
WER игнорирует регистр, пунктуацию и различие е/ё. Это проверка распознавателем:
`missing_spans` могут содержать ошибки ASR, а альтернативные выравнивания могут
по-разному распределять замены и пропуски. RMS не измеряет «железность» и зависит
от содержания речи и пауз. Автоматического победителя тест не назначает.

`report.json` и `summary.*` содержат промежуточные результаты отдельных
генераций. `report.json: complete=true` означает окончание генерации, но ещё
не окончание ASR; для всего теста нужны `comparison.json: complete=true`
и успешное завершение задания. В архивы не попадают reference audio, его
транскрипт, веса, локальный путь ASR-кэша и исходные float WAV.

## Остановка и продолжение

```bash
.venv/bin/python -m fireredtts3_local.sentence_diagnostics stop
```

Текущая генерация или ASR-проверка WAV завершается и сохраняется. Если уже
есть `report.json`, продолжение с теми же входами и версиями кода:

```bash
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 \
  .venv/bin/python -m fireredtts3_local.sentence_diagnostics start \
  --resume --job-dir training/jobs/joint-10-sentences-retry
```

Готовые генерации и ASR-результаты используются повторно после проверки хэшей.
Для просмотра возобновлённого задания укажите его путь в `status` / `stop`.
Если каталог результата ещё не появился, повторите запуск с новым `--job-dir`
без `--resume`. Для другой модели ASR, checkpoint или паузы нужны новые
`--output` и `--job-dir`; параметры `--asr-model`, `--step`, `--pause-seconds`
записываются в план. Предыдущие диагностики сохраняются отдельно.
