# Ещё половина YO: авторизованная загрузка Parquet и локальный отбор

Этот этап готовит данные и не запускает обучение. Источник —
`NCSpeech/YO-CPT-ru`, revision `f2f92c5ecf6b0323cf7e7f9599f0e4852f6c536b`:
379 Parquet, 1 008 879 097 019 байт. Половина определяется **по количеству шардов**:
`ceil(379 × 0.5) = 190` новых файлов, дополнительно к прежней выборке.

Прежние локальные Parquet и записи журнала использованных шардов исключаются.
Новые выбираются воспроизводимо с seed 1234, пропорционально доступным файлам
каждой исходной части `ru000`, `ru001`, `ru100` и т. д. Это около половины объёма
в байтах/часах, а не строго 50% каждого из этих показателей.

Если раньше были загружены `ru000-000`…`ru000-011`, новый план содержит около
**505,13 ГБ / 3030,24 часа исходной речи** до фильтров. Полезный объём определяется
после импорта. План отдельно показывает выбранные байты, освобождаемые байты
старых Parquet и консервативную оценку места для PCM WAV.

## Вход с токеном на GPU-машине

Создайте токен с правами чтения на <https://huggingface.co/settings/tokens>.
Токен вводится только на сервере, в скрытом приглашении; в чат, JSON-рецепт,
командную строку `--token ...` или репозиторий его вставлять не требуется.

```bash
cd /home/firered-tuning
.venv/bin/hf auth login
.venv/bin/hf auth whoami
```

В меню входа выберите **Paste an access token**, вставьте токен в скрытое поле.
На предложение сохранить его в git credentials ответьте `n`.
Авторизация сохраняется в локальном кеше Hugging Face и доступна фоновому
процессу, запущенному тем же пользователем. Код передаёт `token=True`, а не
значение токена. Авторизация может повысить лимиты; скорость также зависит от
сети и диска. Токен не сохраняется в планах или отчётах этой утилиты.

## План и проверки перед удалением

```bash
git pull --ff-only origin feat/russian-tts-adaptation

OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 \
.venv/bin/python -u -m fireredtts3_local.yo_expansion plan \
  --source training/raw/yo \
  --output training/plans/yo-half \
  --fraction 0.5 --seed 1234
```

`plan` ничего не удаляет. Он проверяет старые Parquet по размеру/SHA256 закреплённой
версии Hub, проверяет существующие WAV по сохранённым хешам и записывает точные
списки `old_parquet`, `selected`, исторические manifests и условия фильтрации
в `plan.json`; краткая сводка — `report.json`.

По умолчанию учитываются:

- обучение: `yo-split/train`, `yo-complete-split/train`, `dialogs-neutral/train`;
- отложенные дикторы: `yo-split/validation`, `yo-complete-split/validation`;
- дополнительно защищается `dialogs-neutral/validation`.

Валидация Dialogs содержит знакомых актёров, поэтому она **не** объявляется
speaker-disjoint набором. YO-выборка сохраняет прежние связи local/global speaker,
исходных записей и аудиохешей, включая связи через старые строки, отсутствующие
в новой выборке. Новое соединение старых train/validation идентичностей останавливает
разделение для проверки; утилита не переносит обученного диктора в validation.

## Фоновое скачивание и извлечение

```bash
mkdir -p training/logs
nohup env OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 \
  .venv/bin/python -u -m fireredtts3_local.yo_expansion run \
  training/plans/yo-half/plan.json \
  --output training/datasets/yo-half \
  --delete-old-parquet \
  >> training/logs/yo-half.log 2>&1 < /dev/null &
```

`--delete-old-parquet` удаляет **только старые Parquet из плана** после повторной
проверки исторических WAV и всех удаляемых файлов. Удаление не рекурсивное;
каталоги datasets, models, outputs и кеш признаков не затрагиваются. Исходный
список сохраняется также в `training/raw/yo/used-parquet.json`, поэтому после
очистки эти шарды не попадут в следующий новый план.

Для крупных Parquet используется Xet с локальным токеном: один файл за раз,
внутри Xet может скачивать диапазоны параллельно. При временных сбоях работают
повторы и паузы. При необходимости доступен `--transport http` для той же команды.
Уже завершённые файлы проверяются локально и переиспользуются. Никаких токенов
или параметров обучения в команду добавлять не нужно.

Перед удалением проверяется место под оставшуюся загрузку и консервативную оценку
WAV. Перед каждым новым шардом проверяется свободное место. Полезная выборка обычно
существенно меньше этой оценки, но точный объём заранее неизвестен.

После скачивания всех выбранных Parquet извлечение идёт по одному шарду, пакетами
по 32 записи. Завершённая часть фиксируется атомарно и повторно не извлекается.
Счётчики дикторов и увиденных utterance восстанавливаются при продолжении;
30-минутный лимит не сбрасывается на каждом шарде. Проверка наличия отдельного
референса выполняется **после объединения частей**, чтобы не потерять пару,
разделённую границей Parquet.

Сохраняются:

- русский язык, DistillMOS ≥ 4;
- целые исходные реплики любой положительной длительности;
- окончание `.`, `!`, `?`, без конечного многоточия;
- совпадение слов `text`, `text_denorm` и word alignment;
- моно, корректная длительность, конечные samples и проверка clipping;
- разные непересекающиеся записи того же локального диктора для пары;
- максимум 30 минут на локального диктора **в новой выборке**, без общего лимита часов.

Ранее использованные YO utterance исключаются по исходному ID целиком, даже
если в старом наборе был только их сегмент. Аудиодубликаты прежних и новых WAV
и записи без пары исключаются перед финальным разделением. Их извлечённые WAV
удаляются по отдельному проверенному списку после сохранения итоговых manifests.
Метки `neutral` и квот question/statement/random у этой YO-выборки нет: эти правила
относятся к отдельному этапу Dialogs; YO не содержит аналогичной разметки эмоций.

## Прогресс, продолжение, результат

```bash
tail -f training/logs/yo-half.log
```

SSH можно закрыть, `Ctrl+C` у `tail` останавливает просмотр. Состояние процесса:

```bash
cat training/datasets/yo-half/expansion_state.json
```

После ошибки или перезагрузки повторите ту же команду `run` с тем же планом и
output. Одновременные процессы на один source блокируются. Существующие части
не перезаписываются, иной план для непустого output отклоняется. Состояние в JSON
после аварийного завершения может остаться последним записанным; PID также указан.

При `complete: true` результат:

- `training/datasets/yo-half/train.jsonl` — новые обучающие реплики;
- `validation.jsonl` — новое разделение с сохранением исторических ограничений;
- `manifest.jsonl` — объединённый принятый набор;
- `split_report.json` — реальные часы, дикторы, длины и причины отказов.

WAV находятся внутри `parts/`; **сохраняйте этот каталог** вместе с manifests.
Новые исходные Parquet остаются в `training/raw/yo/data` до следующей осознанной
очистки. Модели и recipe обучения на этом этапе не меняются. По финальному отчёту
выбираем следующий рецепт, предрасчитываем признаки и измеряем GPU-пилот; число
новых шагов заранее не фиксируется.

После получения отчёта переходите к [обучению на расширенной YO-выборке](YO_HALF_TRAINING.md):
один полный проход с Dialogs replay, проверкой новых голосов и отдельной проверкой
диалогов. Рецепт подготавливается и проверяется до запуска GPU.
