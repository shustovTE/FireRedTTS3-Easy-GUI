# Откуда берётся «металл» на длинной реплике

Тест воспроизводит генерации из наборов прослушивания `backbone-complete` двух прогонов на шаге 500. В первом обучались backbone и DiT, во втором обучался только backbone. При диагностике в обоих случаях включена только LoRA backbone, работают исходные DiT и RedAE. Текст синтезируется целиком. Тест сверяет хеши Base, чекпойнтов, референсов и архивных WAV. Перед парным запуском проверяет совпадение текстов, референсов, seed и настроек синтеза.

## Запуск на Gauss

```bash
cd /opt/firered-tuning
git switch feat/russian-tts-adaptation && git pull --ff-only origin feat/russian-tts-adaptation

run_root=training/outputs/firered-vox-recipe-12-cap30m-levels
joint="$run_root/lora-joint-recovery-4patch-0500-backbone-audio/lora/step-0500"
backbone="$run_root/lora-backbone-only-recovery-4patch-0500"
out=training/diagnostics/feedback-pair-0500-at12
mkdir -p training/logs
nohup .venv/bin/python -u -m fireredtts3_local.feedback_probe \
  "$joint" --compare-run "$backbone" --output "$out" \
  > training/logs/feedback-pair-0500-at12.log 2>&1 < /dev/null &
tail -f training/logs/feedback-pair-0500-at12.log
```

По умолчанию идут шесть seed для «Городов» (1234–1239) и два для «Тимофея» (1234–1235). Выйти из просмотра лога можно через Ctrl+C. Повтор команды с теми же параметрами пропускает завершённые случаи после сверки файлов. Для другого опыта укажите отдельную выходную папку. Например, параметры `--cases cities_seed1235 --at-seconds 20 --fraction 0.01` проверяют одну запись на 20-й секунде с возмущением в 1%. Параметр `--cases all` выбирает все записи из исходного набора. Если реплика закончилась раньше точки измерения, в отчёте будет `insufficient_continuation`.

## Что именно меняется

Сначала тест строит контрольный WAV и сравнивает его с архивным по отсчётам PCM. Затем повторяет контроль с тем же seed. Для измерения требуется точное совпадение двух новых генераций по латентным патчам, решениям остановки и PCM. В каждой последующей ветке проверяется состояние генератора шума перед каждым общим шагом DiT и совпадение патчей вплоть до вмешательства включительно. Если `archive_pcm_exact=false`, парное сравнение относится к новому контролю. Сравните его тембр с архивной записью.

По умолчанию в акустическую историю добавляется один фиксированный вектор шума с RMS в 2% от RMS патча, начинающегося на 12-й секунде. Используется отдельный генератор случайных чисел. Все три ветки получают один и тот же вектор. Сохранённый для декодирования патч остаётся исходным. Первое возможное изменение в генерируемых патчах приходится на 12,16 с.

| Файл | В каком месте подаётся изменённый патч |
| --- | --- |
| `control.wav` | Обычная генерация |
| `dit_history.wav` | В прямую историю DiT, пока этот один патч остаётся в её окне из двух патчей |
| `backbone_history.wav` | Один раз на вход PatchEncoder, затем информация проходит через backbone |
| `both_histories.wav` | Одновременно в оба входа |

После вмешательства все предсказанные патчи естественно проходят через оба пути обратной связи. Имена WAV обозначают точку внесения возмущения. Это позволяет проверить чувствительность продолжения, сохранив все компоненты генератора в работе.

## Что смотреть

Начните с `joint/controls/cities_seed1235/` и `backbone-only/controls/cities_seed1235/` в выходной папке. В каждой лежат четыре WAV и таблицы. У каждого чекпойнта свой контроль, а направление и относительная величина возмущения совпадают между чекпойнтами. Результаты отдельного seed доступны в `result.json` сразу после его завершения.

В конце появится общая таблица `comparison.csv`. Столбцы `*_gain_hops3_12` дают медиану усиления возмущения в патчах с 3-го по 12-й после вмешательства. Столбцы `*_tail_delta_db` показывают изменение контраста резонансных полос относительно собственного контроля в одинаковых временных окнах последней трети общей части записей после вмешательства. Пустая ячейка означает, что сравнимых данных недостаточно.

- В `patches.csv` столбец `hop` отсчитывает патчи после вмешательства. `gain` — RMS расхождения двух предсказаний, делённый на RMS внесённого возмущения. Значение 2 означает, что в этом патче расхождение вдвое больше исходного возмущения. На третьем и следующих шагах изменённый исходный патч уже покинул прямое окно DiT.
- В `windows.csv` сравниваются одинаковые интервалы двух WAV вплоть до конца более короткой записи. `rms_delta_db` показывает разницу уровней. `resonance_delta_db` показывает медианное изменение контраста полос около 2,22, 2,97 и 5,19 кГц относительно их соседних частот в кадрах с сигналом в обеих записях.
- В `result.json` указаны длительность и причина завершения каждой генерации. Если в одной ветке слова произнесены в другом темпе или пропущена фраза, спектральные различия на одинаковой секунде могут отражать уже разные звуки речи. Для вывода о «металле» сопоставьте прослушивание с динамикой полос на нескольких seed. Этот тест проверяет чувствительность к одному направлению возмущения и сам по себе не устанавливает экспоненциальный характер роста.
